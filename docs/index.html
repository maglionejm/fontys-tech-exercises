Chapter 1The whole table at once

Each dot is a person

A row in a table is easy to forget. Drawn as 891 dots, the manifest becomes a crowd, and every split the course makes, by class, by sex, by age, is a rearrangement of the same people. Scroll: the dots move, nobody is added or removed.

891 rows, in manifest order

Passenger 1 top-left, passenger 891 bottom-right. Teal dots survived, ember dots did not. In this order the outcome looks like noise. Everything the course does is a search for the order in which it stops looking like noise.

342 survived, 549 died. 38.4% is the number every model must beat.

Sorted by outcome

The same dots, survivors gathered on the left. This is what the target column looks like on its own: imbalanced but not extremely. A model that always says "died" is right 61.7% of the time. That is the floor, not an achievement.

Split by ticket class

Three columns, survivors at the top of each. First class survived at 63%, second at 47%, third at 24%. The column widths are the crowd sizes: more than half the passengers travelled third class.

Split by sex

The strongest single signal in the table. 74% of women survived; 19% of men did. Session 3 of the machine learning module shows that a model given only this column already beats the floor by a wide margin.

Class and sex together

Six groups. First-class women survived at 97%, third-class men at 13%. Two columns explain most of the story, which is why the course spends so long on features before it spends any time on algorithms.

By age, including the 177 blanks

Children under 13 survived at 58%, passengers over 60 at 27%. The hollow dots are the 177 passengers with no recorded age. The first notebook of the ML module fills them with the training set's median, 28.5 years, and never with the test set's.

Module 2Machine learning3 notebooks

Then predict, honestly

Module 2 asks a new question: what will happen to a passenger the model has never seen? The answer has to be a number, and the number has to be earned on rows that were locked away before any learning started.

Train712 rows
Test179 rows

80/20, stratified, random_state=42. The survivor share stays 38% in both halves. The test rows are sealed until the final exam, and opened exactly once.

Notebook M2-03tuning, then a reality check

Eighteen grid combinations, fifteen random ones, and one honest number

Grid search over a Random Forest reached a cross-validated 0.8259; random search reached 0.8274 with a third fewer trials. On the sealed test rows the tuned forest scored 0.8268, below the untuned Logistic Regression's 0.838. Tuning polishes a model; it does not change which model fits the data. That lesson is worth more than the two decimals.

Module 3Architectures and deployment3 notebooks

A trained model is a file. A useful model is a system.

Module 3 puts the model where an application can reach it: behind a FastAPI endpoint, inside a Docker container, on Google Cloud Run or AWS App Runner, and finally into the hands of a web page that calls it over HTTP. The notebooks start a real server and talk to it.

Pattern 1

Batch

Score the whole manifest overnight, write a table. Cheapest, slowest to react.

Pattern 2

Real-time API

One request, one prediction, in milliseconds. What notebooks M3-02 and M3-03 build.

Pattern 3

Streaming

Predictions ride along an event stream as records arrive.

Pattern 4

Embedded

The model ships inside the application. The predictor above is this pattern: eighteen weights in a JSON file.

The 422 is not a failure: it is the API refusing a negative age before the model ever sees it. Validation at the door is half of deployment. The other half, timeouts, retries and error handling, is what the last notebook teaches a client to do.

The courseFour modules, ten notebooks

Start anywhere. Every notebook stands alone.

Click a badge to open a notebook in Google Colab and choose Runtime > Run all. No account, no key, no installation. Or read the executed outputs directly on GitHub.

Module 1Descriptive analytics

  1. Data cleaning

    Missing values, duplicates, wrong types, inconsistent text and outliers, with pandas and NumPy loops.

  2. Descriptive statistics

    Central tendency, spread, distribution shape, frequencies, group comparisons, correlation.

  3. Visualization and dashboards

    Matplotlib, seaborn and Plotly; chart-choice rules; static and interactive dashboards exported as HTML.

Module 2Machine learning

  1. Data prep and feature engineering

    Split first, impute, encode, scale, engineer Title and FamilySize, wire it into one Pipeline.

  2. Model selection

    Six models judged by cross-validation; confusion matrices, precision, recall, F1, ROC AUC; learning curves.

  3. Model optimization and deployment

    Grid and random search, saving with joblib, a Gradio app, a free deployment on Hugging Face Spaces.

Four teaching decks accompany this module: presentations/.

Module 3ML architectures and deployment

  1. ML system architectures

    Data and training pipelines, model registry, four serving patterns, drift monitoring, build versus buy.

  2. Deploying models in the cloud

    FastAPI, tests before shipping, Docker, the same container on Cloud Run and App Runner.

  3. Consuming models from applications

    A real server started in the notebook; requests with timeouts and retries; a web page that calls the model.

Module 4Prompting and language models

  1. The power of prompting

    A small language model runs on your machine; a five-rung prompt ladder scored on real passengers; then the model writes, checks and optimizes its own prompts (APE, Self-Refine, OPRO).

One teaching deck accompanies this module: presentations/.
